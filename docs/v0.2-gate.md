# The v0.2 gate

v0.2 ships when the owner has filed a sample of a real Downloads backlog end to end with the `carrel` CLI and approved the result (issue #3). This is the checklist for that run, and the record of it.

It's a test of the whole path on real files: intake, extraction, card drafting, routing, sensitivity, review, filing, history, undo and backups. It isn't a benchmark of models (that's `docs/design/benchmark.md`), so use the models you'd really use.

## Before

- [ ] **Carrel:** build `dev` (`cargo build --release -p carrel-cli -p carrel-fetch -p carrel-provider-extract -p carrel-provider-llama`, and the Apple provider with `swift build -c release --package-path apple/CarrelProviders`), with the programs together in one folder on `PATH`.
- [ ] **Models:** `carrel providers` shows Apple's model, and `carrel models download gemma-4-e4b` adds the model the benchmark recommends for 16 GB or more (`docs/bench/`). Apple's model drafts first, and Gemma gives a second opinion on what Apple's would send to Holding. `carrel settings` shows both.
- [ ] **A new archive** for the gate, not the sample one: `carrel init ~/Carrel-gate`. Keep it out of iCloud Drive and other synced folders for this run.
- [ ] **Collections:** 6 to 12 top-level collections that fit what's in your Downloads, each made with `carrel collection new NAME --description "…"`. Then open each `_collection.md` and fill in **Purpose and scope** and **Not here**: models read them before filing anything. Overlap is fine; say in **Not here** where the near-misses go.
- [ ] **Originals kept:** in `_System/settings.json`, set `"ingest": {"originals": "keep"}`, so approval copies files in and leaves your Downloads untouched.
- [ ] **Backups (optional):** `carrel backup setup /Volumes/…` to a drive or a folder outside the archive, so each approval batch takes a snapshot.

## The sample

- [ ] Copy (don't move) 50 to 100 items from `~/Downloads` into a staging folder, such as `~/Carrel-gate-in`. Pick them as they come rather than choosing easy ones, but include at least: PDFs with text, a scan or photo of a document, something sensitive (a statement, a payslip, a medical letter), a code project folder, and a couple of things that belong nowhere obvious.

## The run

1. [ ] `carrel ingest --dry-run --each ~/Carrel-gate-in`: check the plan (kinds, duplicates, skipped files) before anything is drafted.
2. [ ] `carrel ingest --each ~/Carrel-gate-in`: queues every item and returns; a worker drafts, routes and rates them one at a time in the background. Follow it with `carrel ingest --status` (or add `--wait` to stay with a progress bar), and note how long it takes. Proposals appear in Review as each is ready.
3. [ ] `carrel`: in the interactive mode, go through **Questions** first (answers improve the drafts waiting on them), then **Review**: approve, move (`m`), hold (`h`), edit (`e`) or reject (`x`) each proposal.
4. [ ] Approve in batches; each is one history change, and one snapshot if backups are set up.
5. [ ] Check the result: `carrel status` (including the new **Structure** section), **Browse** in the interactive mode, and the archive folder in Finder and in Obsidian.
6. [ ] Undo one batch from **History** (`u`), check the items went back, then approve it again.

## Passing

The gate passes when:

- every item in the sample is filed, held or deliberately rejected, with nothing lost or changed;
- no sensitive or restricted item was filed without waiting for approval;
- most proposals needed no more than a move or a small edit (record how many did);
- undo restored a batch exactly;
- and the owner is willing to start using it on the rest of the backlog.

Anything that doesn't pass becomes an issue in the v0.2 milestone, fixed before the release, or moved to v0.3 if it can wait.

## Result

**Passed 2026-10-30.** The owner is happy with the state of ingest and will use it on the rest of the backlog; more quality control comes once collections are determined and reassessed dynamically (#154).

Found and fixed during the gate:

- Sensitivity was over-rated, mostly from model guesses on files with no text and digit runs mistaken for card numbers (#190).
- Corrections in plain words, in Review and on filed items, with refiling (#187, #191), made to stay in the interactive mode (#192, #193) and to keep models from inventing dates or lowering sensitivity (#194).
- `carrel formats` and a per-device log of the file types nothing reads (#184).

Left for later: better questions (#195), reading images, 3D models and compressed files (v0.3: #179, #182, #185).
