# The v0.3 gate

v0.3 ships when one real project has gone through a full checkout and return with the `carrel` CLI and its interactive mode, and the owner is happy with the result (issue #4). This is the checklist for that run, and the record of it.

It tests working on something already in the archive: checking it out, the work being noticed and recorded while it happens, and bringing the new version back safely. v0.2's gate tested filing; this one tests everything after.

## Before

- [ ] **Carrel:** build and install `dev` as for v0.2 (`docs/guide/getting-started.md`), including the Apple provider, so `carrel --version` is the latest.
- [ ] **Backups:** `carrel backup setup` to a drive or a folder outside the archive. The checkout, each work session and the return take snapshots, and the gate checks them.
- [ ] **The project:** an item in your archive that you'll really work on over the next day or more: ideally a folder with a Git repository (a code project, a paper in LaTeX), so commits count too. Not a huge dataset; for one of those, add `snapshots: return-only` to its card first.
- [ ] **Something for the desk (optional):** a folder you're working on that isn't in the archive yet, to try desk items alongside.

## The run

1. [ ] **Check it out:** `carrel checkout ITEM` (or `--to FOLDER`, and `--due DATE` if you like). Check:
   - the copy is where it said, and it's tagged **Checked Out** in Finder;
   - the archive copy is read-only, and its card says where it went;
   - `Active/Checked out/` in Obsidian lists it.
2. [ ] **Put something on the desk (optional):** `carrel desk add PATH`. A card appears beside it, drafted by a model, and `Active/On desk/` mirrors it.
3. [ ] **Work on it normally**, in your usual editor or IDE, over at least a day: a few stretches of work, with commits if it's a repository. Don't do anything special for Carrel.
4. [ ] **Watch it:** open `carrel` and go to **Active** (`3`). While you work, Carrel looks for finished sessions every few minutes, and whenever you run a command that changes the archive. Check:
   - each finished stretch of work shows up as a pending history entry, with the files changed, the commits and the time spent;
   - with backups, each one has a session snapshot (`carrel backup list`).
5. [ ] **Decide the entries:** approve (`a`), combine (`c`), drop (`d`) or edit (`e`) them on the Active screen, or with `carrel sessions`. Try approving one by hand in Obsidian too, and check Carrel notices.
6. [ ] **Return it:** `r` on the Active screen, or `carrel return ITEM`. It shows what changed, the commits and the history entry it adds, and asks first. Then check:
   - the archive copy is the new version, and unlocked; the Finder tag is gone;
   - a snapshot holds the returned version, and Carrel offered to forget the session snapshots;
   - the card's history has the entries, and the Journal for this month lists them;
   - the working copy is still where it was, for you to delete when you're ready.
7. [ ] **Get the old version back:** `carrel backup restore ITEM --at CHANGE`, with the change before the return from **History**, puts the version from before your work in a new folder beside the archive, leaving the archive as it is. History holds cards, not files, so undoing the return (`u`) puts the card back but not the old files; check that it says so, and that `backup restore` is the way to recover them.
8. [ ] **Cancel one (optional):** check something out, change it, and cancel with `x` on the Active screen or `carrel return ITEM --discard`: the archive copy is as it was.

## What to record

| Measure | Result |
| --- | --- |
| The project (kind, size, Git or not) | |
| How long it was out, and how many stretches of work | |
| Sessions found, and whether they matched the work you did | |
| Entries approved, combined, edited or dropped | |
| Session snapshots taken, and forgotten on return | |
| Anything in the return's list of changes you didn't expect | |
| Anything lost, changed or misplaced (should be none: the return is checked before it swaps) | |
| The old version came back with `backup restore`, and undo explained what it does and doesn't restore | |
| Desk item tried, and how its drafted card was | |
| Anything confusing in the Active screen or the commands | |

## Passing

The gate passes when:

- the project went out and came back with nothing lost, and the archive copy was safe while it was out;
- the work was noticed and recorded as sessions you'd keep, give or take some combining or editing;
- the version from before the work could be recovered exactly from backups;
- and the owner is willing to use checkout for their real projects.

Anything that doesn't pass becomes an issue in the v0.3 milestone, fixed before the release, or moved to a later milestone if it can wait.
